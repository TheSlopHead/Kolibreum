# Исправления безопасности мобильного приложения

Реализация этапов 1 и 2 из [корневого плана](../../docs/SECURITY_FIXES.md), обновлено 2 октября 2026. Изменения ограничены `mobile/`, включая Kotlin-мост Android SAF и мобильный формат v2. Десктопные Go/Wails-компоненты не изменены.

| Проблема | Статус и поведение |
| --- | --- |
| SEC-01 | Блокировка отменяет ожидающий picker, затирает Android-буфер экспорта и очищает Dart-байты. Операции имеют отдельные request code и deadline 5 минут; старые ответы не запускают экспорт в новой сессии. Запись проверяет отмену между блоками под общим с очисткой монитором. |
| SEC-03 | Вложенные FB2-параграфы извлекаются один раз. Один StringBuffer устраняет повторные копии на каждом уровне XML. Суммарный лимит параграфов FB2/EPUB — 16 Ми UTF-16 code units; превышение возвращает `LibraryFailure('limit', ...)`. |
| SEC-04 | После открытия каталога в staging проверяется точное совпадение файлов backup с текущими header, HEAD, snapshot и достижимыми объектами. Лишние или отсутствующие файлы отклоняются; действующий сейф не заменяется. |
| SEC-05 | Перед формированием backup проверяется AEAD архивируемых snapshot/objects, размер/hash оригиналов и соответствие header/каталога текущей сессии. Ошибка объекта указывает книгу. Проверочный plaintext очищается также при исключении. |
| SEC-02 | **Исправлена для мобильного v2.** HKDF info — `mut:object:<id>` / `mut:snapshot:<id>`, AAD — `object:<id>` / `snapshot:<id>`. Новые архивы имеют `vault.json.version = 2`; старые мобильные v1 мигрируют после открытия в отдельном каталоге, с перешифрованием достижимых оригиналов, обложек и каталога. Подстановка объекта вместо snapshot вызывает ошибку `authentication`. |

## SEC-02: формат и миграция

Криптографическая версия определяется только `vault.json.version`. После отказа AEAD в v2 нет повторной попытки с ключами/AAD v1; редактирование заголовка v2 в `version: 1` тоже не открывает архив. JSON-схема каталога и ZIP-манифест сохраняют собственный `version: 1`, который не определяет криптографический режим. Байтовый контракт и тестовые векторы описаны в [VAULT_FORMAT.md](VAULT_FORMAT.md).

Для v1: проверка секрета и каталога → проверка AEAD, размера/hash оригиналов и обложек → запись только достижимых сущностей с v2 KDF/AAD в `.migrate-<uuid>` → повторное открытие и проверка → перенос источника в `vault.v1` → замена рабочей директории подготовленной v2. Пароль, recovery code, UUID, метаданные, позиции и закладки сохраняются. Исходные encrypted файлы остаются в `vault.v1`; старые резервные копии не переписываются. Plaintext обрабатывается в памяти и не записывается в staging.

Маркер `vault.migration` позволяет после прерывания между переносами вернуть v1-источник. Незавершённый staging не становится рабочим архивом. Для прерванного restore без маркера выбирается `vault.previous`, даже если сохранена более старая `vault.v1`. `flush`/`rename` не являются обещанием directory fsync или полной устойчивости к аппаратному сбою.

При восстановлении v1 backup сначала проверяется его исходный точный граф и все объекты; затем v2 создаётся в staging до замены действующей библиотеки. При ошибке действующий архив остаётся прежним. Сохранённая `vault.v1` не удаляется автоматически; если при повторной миграции такая копия уже существует, операция отклоняется.

Старый формат v1 и сохранённые копии v1 остаются подвержены исходной подмене. Миграция не может задним числом доказать, что каталог v1 не был подменён до открытия. SEC-02 закрыта для активного v2, а не для исторических ciphertext. Возврат к старым согласованным header/HEAD/ciphertext, включая v1, не предотвращается; замена одной версии без соответствующих legacy ciphertext отклоняется. Защита от rollback и неизменяемый внешний якорь версии в этот фикс не входят.

Go-коммит `c3ba874` в `origin/main` разделяет HKDF по типу; его snapshot AAD ещё равен UUID, а header остаётся v1. Go-ядро здесь не менялось. Независимый **мобильный** скрипт `tool/go_vectors.go` проверяет контракт мобильного v2 через Go-примитивы; это не объявление совместимости всего архива с текущим Go-клиентом.

Отмена не удаляет незашифрованные экспорты, завершённые раньше, и не отзывает байты, уже переданные провайдеру до отмены. Системный picker может оставаться открытым, но его результат после отмены игнорируется. Очистка runtime-копий памяти остаётся best effort. При недоступном платформенном канале блокировка сейфа всё равно выполняется.

Регрессии находятся в `test/security_audit_test.dart`, `test/documents_test.dart`, `test/book_decoder_test.dart`, `test/vault_migration_test.dart` и `test/crypto_compatibility_test.dart`. Проверяются подмена объекта вместо каталога, независимое разделение KDF/AAD, отсутствие legacy fallback, миграция паролем/recovery, пустой v1, повреждённые оригиналы/обложки, backup/restore и восстановление после прерванного переноса, а также проверки этапа 1.

Команды проверки:

```sh
flutter analyze --no-pub
flutter test --no-pub
flutter test --no-pub tool/verify_go_v2.dart
flutter build apk --debug --no-pub
```

Flutter-тесты используют подмену Documents и не исполняют Android ContentResolver. Реальные SAF-переходы, медленный провайдер и уход в фон необходимо дополнительно проверить на устройстве по процедуре [RELEASE.md](RELEASE.md).

Проверка двусторонних криптографических байтов выполняется отдельно: обычные тесты читают независимые Go-векторы v1/v2; `tool/verify_go_v2.dart` создаёт ciphertext Dart-кодеком и проверяет его Go-скриптом. Для последнего нужен установленный Go и зависимости модуля. Проверка компиляции Kotlin-моста и Linux-тесты не заменяют ручной тест SAF на устройстве.

Проверка 2 октября 2026: анализ без замечаний; общий прогон `test`, двусторонней проверки Go и генератора скриншотов — 85 тестов прошли. Отдельно проверены 11 сценариев миграции. Debug APK собран в `build/app/outputs/flutter-apk/app-debug.apk`. Этот результат не является независимым security review.
