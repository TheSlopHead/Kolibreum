# Исправления безопасности мобильного приложения

Реализация этапа 1 из [корневого плана](../../docs/SECURITY_FIXES.md), 1 октября 2026. Изменения ограничены `mobile/`, включая Kotlin-мост Android SAF. Десктопные Go/Wails-компоненты и формат сейфа v1 не изменены.

| Проблема | Статус и поведение |
| --- | --- |
| SEC-01 | Блокировка отменяет ожидающий picker, затирает Android-буфер экспорта и очищает Dart-байты. Операции имеют отдельные request code и deadline 5 минут; старые ответы не запускают экспорт в новой сессии. Запись проверяет отмену между блоками под общим с очисткой монитором. |
| SEC-03 | Вложенные FB2-параграфы извлекаются один раз. Один StringBuffer устраняет повторные копии на каждом уровне XML. Суммарный лимит параграфов FB2/EPUB — 16 Ми UTF-16 code units; превышение возвращает `LibraryFailure('limit', ...)`. |
| SEC-04 | После открытия каталога в staging проверяется точное совпадение файлов backup с текущими header, HEAD, snapshot и достижимыми объектами. Лишние или отсутствующие файлы отклоняются; действующий сейф не заменяется. |
| SEC-05 | Перед формированием backup проверяется AEAD архивируемых snapshot/objects, размер/hash оригиналов и соответствие header/каталога текущей сессии. Ошибка объекта указывает книгу. Проверочный plaintext очищается также при исключении. |
| SEC-02 | **Не исправлена.** По корневому плану относится к этапу 2: KDF/AAD с типом сущности, формат v2 и миграция. Сохранён воспроизводящий тест `REPRO SEC-02`; успешный прогон тестов не означает устранения этой проблемы. |

Отмена не удаляет незашифрованные экспорты, завершённые раньше, и не отзывает байты, уже переданные провайдеру до отмены. Системный picker может оставаться открытым, но его результат после отмены игнорируется. Очистка runtime-копий памяти остаётся best effort. При недоступном платформенном канале блокировка сейфа всё равно выполняется.

Регрессии находятся в `test/security_audit_test.dart`, `test/documents_test.dart` и `test/book_decoder_test.dart`. Проверяются ручная/автоматическая блокировка ожидающего экспорта, позднее чтение после смены сессии, отсутствие задержки блокировки из-за платформы, вложенные FB2, общий лимит EPUB, лишние/недостающие файлы backup, повреждение объекта/snapshot, неизменность действующего сейфа и удаление staging при отказе.

Команды проверки:

```sh
flutter analyze --no-pub
flutter test --no-pub
flutter build apk --debug --no-pub
```

Flutter-тесты используют подмену Documents и не исполняют Android ContentResolver. Реальные SAF-переходы, медленный провайдер и уход в фон необходимо дополнительно проверить на устройстве по процедуре [RELEASE.md](RELEASE.md).

Результат проверки реализации: `flutter analyze --no-pub` — без замечаний; `flutter test --no-pub` — 54 теста прошли, включая оставленный REPRO SEC-02; debug APK успешно собран в `build/app/outputs/flutter-apk/app-debug.apk`. Это проверка компиляции Kotlin-моста, а не ручной тест SAF на устройстве.
