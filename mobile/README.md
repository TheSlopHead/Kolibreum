# mut · Android

Flutter-приложение для локальной зашифрованной библиотеки. Интерфейс перенесён из [Paper, M01–M08](https://app.paper.design/file/01M3PX4ZS5H909QX385GZP43FJ/p-1-0): графитовые поверхности, серебристый акцент, Onest и Literata, обложки, нижняя навигация и панель продолжения чтения. Шрифты и логотип включены в пакет; приложение не скачивает их при запуске.

## Запуск

Нужны Flutter 3.47.5 / Dart 3.13.4 или совместимая стабильная версия, JDK 21 и Android SDK. Минимальная версия Android — 8.0 / API 26. Compile/target SDK задаёт Flutter; в проверенной конфигурации compile SDK 36, NDK 28.2.13676358.

```sh
cd mobile
flutter pub get
flutter analyze
flutter test
flutter run
flutter build apk --debug
flutter build apk --release --target-platform android-arm64 --split-per-abi
```

Укажите пути к SDK через `ANDROID_HOME`, `JAVA_HOME` и `android/local.properties` в своей среде. `pubspec.lock` фиксирует зависимости. SDK, Gradle-кэш, ключи подписи и локальные пути не входят в исходники. Для release обязателен отдельный ключ и `android/key.properties`; при их отсутствии сборка завершается ошибкой. Debug-сборки используют отладочный ключ.

APK для локальной установки на arm64-устройство: `build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`. После подключения телефона: `adb install -r build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`.

Для подготовленного локального окружения Android-эмулятор запускается командой `./tool/start-emulator.sh`, приложение — `./tool/run-android.sh`. Во время `flutter run` нажмите `r` для hot reload или `R` для hot restart. Аргументы Flutter можно передать скрипту, например `./tool/run-android.sh -d emulator-5554`. Скрипты используют постоянные SDK из игнорируемой папки `.tooling/` и стандартную установку Flutter при её отсутствии.

## Продолжение на другом компьютере

Переносите весь Git-репозиторий: мобильные документы ссылаются на корневые спецификации, а генератор тестового Go-вектора использует корневые `go.mod` и `go.sum`. Без push историю можно передать через bundle:

```sh
# На текущем компьютере, из корня репозитория
git bundle create ../mut-mobile.bundle main
# На другом компьютере, после копирования bundle
git clone -b main /path/to/mut-mobile.bundle Mut
cd Mut/mobile
```

Установите указанную выше версию Flutter, JDK и Android SDK, добавьте Flutter в `PATH` и задайте `JAVA_HOME` / `ANDROID_HOME`. Выполните `flutter doctor -v`, примите лицензии через `flutter doctor --android-licenses`, затем выполните команды из раздела «Запуск». Для первой установки зависимостей и Android-инструментов нужен интернет. `android/local.properties`, Gradle wrapper (`gradlew`, `gradlew.bat`, `gradle-wrapper.jar`) и регистрация плагинов создаются Flutter автоматически; копировать `.tooling/`, `.dart_tool/` и `build/` не требуется. Для эмулятора создайте AVD и задайте его имя через `MUT_ANDROID_AVD_NAME` либо выберите устройство командой `flutter run -d <device-id>`.

Для версии **0.1.0+2** подготовлены release-конфигурация и [описание изменений](docs/releases/0.1.0.md). Команда `./tool/prepare-release.sh` из `mobile/` проверяет код, собирает подписанный arm64 APK и сохраняет APK, SHA-256 и сведения о коммите в `build/releases/v0.1.0/`. Требуется чистый закоммиченный `mobile/`. Скрипт не создаёт тег и не отправляет данные в GitHub.

Перед публикацией остаётся:

- Сохранить резервную копию release-ключа и приватного `android/key.properties` отдельно от Git. Постоянный `applicationId` — `dev.mut.mut_mobile`; без исходного ключа нельзя продолжить обновления APK, подписанного этим ключом.
- Проверить на реальном устройстве импорт и чтение PDF/EPUB/FB2, системный выбор и сохранение файлов, блокировку, восстановление backup после переустановки и обновление поверх предыдущей подписанной версии. Unit/widget-тесты не проверяют Android SAF и реальный PDFium.
- Завершить независимое ревью и проверки из [SECURITY.md](../docs/SECURITY.md), разобрать ограничения прототипа ниже, добавить окончательную лицензию проекта и проверить лицензии распространяемых зависимостей.

Порядок подготовки APK и ручной публикации в GitHub описан в [RELEASE.md](docs/RELEASE.md). Публикация не автоматизирована; этот документ не создаёт релиз или тег.

## Что работает

- Создание архива, подтверждение пароля, локальный recovery code, открытие паролем/кодом, смена пароля.
- Импорт файла любого расширения через Android Storage Access Framework. SHA-256 исходника определяет дубликаты; можно пропустить или сохранить отдельную редакцию. Исходный файл остаётся у пользователя.
- Библиотека с ленивой сеткой, фильтры All / Reading / Unread, пользовательские полки, поиск по названию и автору только в памяти.
- Карточка книги, редактирование метаданных, перенос на полку, явный экспорт незашифрованного оригинала в выбранное системным диалогом место. Меню `…` → `Remove from library` удаляет книгу, её прогресс и закладки из текущего каталога после подтверждения. Исходник и старые backup сохраняются; недостижимый ciphertext пока не очищается.
- EPUB/FB2: безопасный упрощённый текстовый ридер, оглавление, переход по главам и страницам, закладки, восстановление позиции, размер текста, цвет страницы и интервал. В `Aa` доступны `Pages` (горизонтальное перелистывание) и `Scroll` (вертикальная лента); режим сохраняется в архиве. Строка `страница / всего · %` соответствует Paper M04. Разбиение зависит от экрана и настроек; текст измеряется порциями, видимые страницы строятся лениво, сохранение позиции не перестраивает экран. Метаданные извлекаются при первом чтении; импорт не зависит от успешного парсинга.
- PDF: PDFium через pdfrx, постраничное чтение с pinch-to-zoom и вертикальная лента с масштабированием, исходный номер страницы, переход к странице, сохранение позиции и закладок. Один документ используется при смене режима. Нет обещания переразметки PDF или OCR.
- Зашифрованная ZIP-копия с манифестом SHA-256 ciphertext, повторное чтение сохранённой копии через SAF, восстановление с проверкой AEAD каждого оригинала в отдельном каталоге.
- Немедленное скрытие содержимого при уходе с экрана, блокировка при уходе в фон и после 5 минут без касаний; Android `FLAG_SECURE` защищает снимок в recents. Системный выбор/сохранение документа — отдельная явная операция, при которой книга не показывается поверх системного диалога.

При первом запуске создаётся **пустая** библиотека. Тестовые книги из Paper не выдаются за пользовательские файлы; они находятся только в тестах.

## Границы прототипа

Это рабочий вертикальный срез, а не прошедший аудит продукт. Исходные [SECURITY.md](../docs/SECURITY.md) и [ROADMAP.md](../docs/ROADMAP.md) по-прежнему требуют независимого ревью до публичного релиза.

- Файл до 32 МиБ, зашифрованная копия до 128 МиБ, распакованный backup до 256 МиБ. Большие объекты и тысячи книг требуют потокового блочного формата и профилирования; текущий Go-прототип тоже хранит объект целиком.
- EPUB/FB2 отображаются как текст: без CSS книги, картинок, скриптов, внешних ссылок, аудио, DRM и сложной fixed-layout вёрстки. FB2 сейчас требует UTF-8. Названия/авторы до первого чтения можно отредактировать вручную.
- Новые текстовые позиции — `text-v2:chapter:characterOffset`, PDF — `pdf-v1:page`. Старые `text-v1:chapter:scrollFraction` и закладки читаются с приблизительным пересчётом. При смене размеров текста восстанавливается страница, содержащая сохранённое место; номер страницы меняется вместе с вёрсткой. EPUB CFI пока не реализован. PDF-закладки доступны в меню оглавления.
- После восстановления прежний архив сохранён как `vault.previous`. Следующее восстановление блокируется, пока владелец не разберёт эту копию: автоматического уничтожения старой библиотеки нет.
- `flush` и `rename` обеспечивают упорядоченную запись/атомарную замену файла; Dart не предоставляет здесь directory fsync. Устойчивость к внезапному отключению питания и crash-testing остаются отдельным этапом.
- В Dart и PDFium очистка памяти best effort; нет обещания гарантированного стирания. Код восстановления показывается один раз и не копируется в clipboard автоматически.
- Проверена совместимость **криптографического байтового представления** с Go; полная миграция между приложениями не объявлена готовой, пока Go-каталог и backup API не завершены.

Подробности границ, потоков данных и решений — [архитектура Android](docs/ARCHITECTURE.md). Точные экспорты макетов — `docs/paper-*.txt`, экранные эталоны — `test/goldens/`.

## Проверки

`flutter test` проверяет round trip архива, произвольный формат, дубликаты, удаление и reimport, повреждение ciphertext, смену пароля и recovery, отказ от повреждённого backup без замены текущей библиотеки, ZIP path traversal/лимиты, EPUB spine, фильтрацию активного содержимого, экраны трёх размеров и гонку чтения с блокировкой. Тесты ридера проверяют длинные Unicode-абзацы без потери символов, ленивую отрисовку, смену режимов/размера текста, восстановление места, сохранение при блокировке и PDFium на сгенерированном трёхстраничном PDF.

Независимый Go-вектор воспроизводится так:

```sh
# Из корня репозитория
go run mobile/tool/go_vectors.go > mobile/test/fixtures/go-vault-v1.json
cd mobile
flutter test test/crypto_compatibility_test.dart
```

Для намеренного обновления экранных эталонов после изменения дизайна: `flutter test test/ui_test.dart --update-goldens`.
