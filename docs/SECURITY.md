# Безопасность и границы доверия

Это инженерная модель угроз для реализации, а не обещание абсолютной защиты. Независимое ревью криптографического формата и обработки недоверенных книг обязательно перед публичной версией с заявленной защитой данных.

## Что защищаем

Содержимое книг, названия, обложки, полки, заметки, позиции чтения, локальные запросы к AI и секреты доступа. Владелец контролирует исходные файлы и пароль. Приложение не создаёт аккаунт и не обращается к серверу для обычной работы.

| Угроза | Мера | Граница |
| --- | --- | --- |
| Украден выключенный диск / копия папки сейфа | AEAD для содержимого и метаданных; пароль через Argon2id; длинный уникальный пароль | Видны факт существования сейфа и некоторые характеристики файлов; для всего диска полезно шифрование ОС. |
| Повреждение/подмена файла | AEAD, контрольные суммы копии, проверка восстановления | Откат всей папки к старой валидной версии без внешнего эталона не обнаружить. |
| Вредоносный PDF/EPUB/FB2 | Парсерные лимиты, отключение скриптов и сети, обновления движков, тестовый корпус | Уязвимость WebKit/PDF.js или приложения возможна; нужна реакция на CVE. |
| Украденный пароль / заражённый разблокированный ПК | Минимальный срок жизни сессии, автоматическая блокировка по таймеру, никакой телеметрии | Шифрование не спасает от программы, читающей открытые данные. |
| Потеря устройства или пароль забыли | Вторая проверенная копия, recovery key, тест восстановления | Нет «сброса пароля по почте»; потеря обоих секретов необратима. |
| Сервис будущей синхронизации | Передача только ciphertext, TLS, шифрование до отправки | Сервер может видеть учётную запись, объёмы и времена обмена; сервис может удалить/не доставить данные. |

Подробное описание границ похожего класса хранилищ: [Cryptomator Security Target](https://docs.cryptomator.org/security/security-target/). Целостность копий и проверку контрольных сумм рекомендует [Digital Preservation Coalition](https://www.dpconline.org/handbook/organisational-activities/storage).

## Ключи и пользовательский опыт

При создании показать фразу: «Пароль известен только вам. Без пароля или кода восстановления архив открыть нельзя». Recovery key генерировать локально, предложить записать/распечатать, затем провести короткую проверку. Не включать секрет в обычный экспорт, логи, буфер обмена по умолчанию и диагностические файлы. Восстановление после смены пароля проверять в CI. Повторные попытки разблокировки не должны превращаться в ложную защиту от офлайнового перебора: важны сильный пароль и параметры KDF.

Файлы на диске зашифрованы всегда. Когда пользователь открыл книгу, её страницы отображаются в webview в открытом виде: запретить внешние запросы и нежелательные копии/кеширование, но честно признать границы памяти ОС. Операция «экспортировать исходник» или «открыть внешне» (для форматов без встроенного адаптера чтения, см. ARCHITECTURE.md) намеренно создаёт **незашифрованный** файл; интерфейс ясно показывает путь и не обещает его последующее безопасное удаление.

Хранение файла произвольного формата, для которого нет адаптера чтения, не парсит его содержимое и потому не увеличивает площадь атаки: до момента, когда пользователь явно запросит «открыть внешне», такой файл — непрозрачные байты за AEAD, как и любой другой объект сейфа. Риск появляется только при попытке отобразить содержимое, а не при его хранении.

## Обмен: модель будущей капсулы

- Выбирать каждый передаваемый объект явно; экспортировать новый независимый пакет, зашифрованный для проверенного публичного ключа адресата. Никогда не отдавать ключ всего сейфа, пароль, внутренние ID и историю библиотечного архива.
- Ключ получателя сверяется вне канала передачи (отпечаток/QR); интерфейс показывает, кому именно предназначен пакет. «Один адресат» означает один список разрешённых получателей, не невозможность копировать уже открытый файл.
- В состав пакета входят только выбранные файлы и явно выбранные метаданные; личные заметки, пути и история чтения исключены по умолчанию. Перед импортом показывать содержимое пакета и безопасно проверять формат.
- Обмен файлом реализовать после правовой и abuse-оценки. Первый социальный сценарий — обмен полками без файлов и собственными заметками. Публичный индекс шифрованных книг не планируется: шифрование не меняет права на распространение произведений. См. [WIPO FAQ](https://www.wipo.int/en/web/copyright/faq-copyright).
- Ограничение содержимого капсулы (собственные произведения, общественное достояние, материалы с явным разрешением правообладателя на распространение) — постоянный принцип, а не временная мера до анализа рынка или юрисдикции запуска. Он не создаёт исключения для книг, запрещённых государством: шифрование пакета защищает канал передачи между двумя доверяющими друг другу людьми, но не меняет статус прав на сам текст, и продукт не проектируется как способ отличать «государство запретило» от «правообладатель не согласен» — с точки зрения возможностей капсулы это одно и то же действие.
- Прототип обмена использовать совместимый с [age](https://github.com/FiloSottile/age) формат получателей, затем тестировать импорт внешней утилитой и обратный импорт. Не придумывать собственную асимметричную схему.

## AI только локально, отдельный этап

AI **выключен по умолчанию** и не участвует в открытии библиотеки. Адаптер связывается только с явно указанным локальным endpoint; запретить удалённые адреса, перенаправления и прокси в режиме «только локально», проверить IPv4/IPv6 и поведение DNS. Проверить, что выбранная модель действительно локальна: один и тот же движок может предлагать облачные модели. Никакого автоматического скачивания модели при открытии книг. Экран согласия показывает модель, процесс, объём данных и то, что локальный процесс получает фрагменты книги в открытом виде. Предупреждать о сторонних расширениях/логах движка.

Поиск с цитатами требует извлечения и индексации текста, которые тоже остаются локальными; индекс зашифрован на диске либо эфемерен. Ответ указывает книгу и позицию, а не выдаёт неподтверждённые пересказы. Отдельный режим полностью офлайн должен проходить сетевой тест с заблокированной сетью. Источник о локальных и облачных вариантах одного движка: [Ollama](https://ollama.com/blog/launch).

## Обязательные проверки до 1.0

- Тестовые векторы шифрования, порчи блока, nonce, параметров KDF и смены пароля; fuzzing декодера формата и импортёров.
- Краш в каждой точке импорта и замены `HEAD`; после перезапуска либо старый, либо новый согласованный снимок.
- Восстановление на чистой VM без исходного приложения и сети из документированного архива, затем сравнение каждого файла по хешу исходника.
- Тесты EPUB с JS, внешними URL, огромной распаковкой; PDF с некорректной структурой; FB2 с опасными XML-конструкциями.
- Пакетный аудит исходящих соединений и содержимого логов до и после разблокировки; тест запрета внешних ресурсов.
- Внешняя оценка дизайна протокола/реализации и исправление замечаний; публичная спецификация версии, миграция и политика сообщений об уязвимостях.
