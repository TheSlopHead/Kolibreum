# mut · План устранения проблем безопасности (SEC-01 — SEC-05)

Документ описывает пошаговый порядок исправления выявленных проблем безопасности в мобильном клиенте `mut` (`mobile/`).

План разделён на два этапа:
1. **Этап 1 (Релиз 0.1.0):** исправления без изменения формата хранилища. Устраняются локально в коде мобильного приложения перед распространением APK.
2. **Этап 2 (Формат v2):** криптографическое разделение доменов (Domain Separation). Требует синхронизации схемы с Go-ядром десктопа и процедуры миграции существующих сейфов.

---

## Этап 1: Быстрые исправления для мобильного приложения (без миграции формата)

### Шаг 1. Исправление SEC-01: Отмена экспорта и очистка нативного буфера при блокировке
* **Цель:** гарантировать, что открытые байты книги не остаются в памяти Android и не могут быть записаны на диск после того, как сработал таймер бездействия или пользователь заблокировал сейф.
* **Затрагиваемые файлы:**
  * `mobile/android/app/src/main/kotlin/dev/mut/mut_mobile/MainActivity.kt`
  * `mobile/lib/platform/documents.dart`
  * `mobile/lib/app/library_controller.dart`
* **Шаги реализации:**
  1. **В `MainActivity.kt`:**
     * Добавить метод в обработчик `dev/mut/documents`: например, `"cancel"`.
     * При вызове `"cancel"`:
       * Немедленно затирать буфер нулями: `output?.fill(0); output = null`.
       * Если висит `pending`, завершать его ошибкой или отменой: `pending?.error("cancelled", "Operation was cancelled by lock.", null); pending = null`.
     * В методе `onStop()`: если системный диалог SAF закрывается или приложение уходит в фон, проверять актуальность сессии.
  2. **В `documents.dart`:**
     * Добавить в интерфейс `Documents` метод `Future<void> cancel()`.
     * В `AndroidDocuments` реализовать его вызовом `channel.invokeMethod('cancel')`.
  3. **В `library_controller.dart`:**
     * В начале метода `lock()` добавить вызов `documents.cancel()` перед занулением внутренних структур данных.

---

### Шаг 2. Исправление SEC-03: Защита парсера FB2 от раздувания текста (XML Amplification / DoS)
* **Цель:** предотвратить лавинообразное разрастание строк в памяти и OOM-краш при открытии файлов со вложенными тегами параграфов.
* **Затрагиваемые файлы:**
  * `mobile/lib/data/book_decoder.dart`
* **Шаги реализации:**
  1. **Исключение вложенных `<p>` (по аналогии с EPUB):**
     * При выборке параграфов из секции проверять предков элемента:
       ```dart
       // Не брать <p>, если он уже находится внутри другого <p>, blockquote или li
       !e.ancestors.takeWhile((a) => a != section).whereType<XmlElement>().any(
         (a) => const ['p', 'blockquote', 'li'].contains(a.name.local),
       )
       ```
  2. **Ограничение суммарного объёма текста книги:**
     * Ввести счётчик накопленной длины символов параграфов.
     * Если суммарная длина превышает лимит (например, 16 или 32 МиБ), прерывать парсинг с контролируемой ошибкой:
       `throw const LibraryFailure('limit', 'Book text exceeds supported limits.');`

---

### Шаг 3. Исправление SEC-04: Строгая валидация состава файлов при восстановлении из бэкапа
* **Цель:** не допустить попадания в каталог сейфа посторонних неаутентифицированных файлов из модифицированного ZIP-архива.
* **Затрагиваемые файлы:**
  * `mobile/lib/data/vault_store.dart`
* **Шаги реализации:**
  1. В методе `restore()` после успешного считывания и расшифровки снимка каталога (`verifier.unlock()`):
     * Собрать полный белый список допустимых путей:
       * `vault.json`
       * `HEAD`
       * `snapshots/<current_head_id>`
       * Все `objects/xx/<object_id>`, на которые ссылаются книги из активного каталога (`verifier.books()`), а также их обложки (если они хранятся как отдельные объекты).
  2. Сверить файлы из распакованного ZIP (`files.keys`) с этим белым списком.
  3. Если в архиве присутствуют любые лишние файлы (не входящие в граф достижимых объектов каталога), прерывать операцию с ошибкой `LibraryFailure('restore', 'Backup contains extraneous unverified files.')` и удалять staging-каталог.

---

### Шаг 4. Исправление SEC-05: Проверка целостности объектов перед созданием резервной копии
* **Цель:** не позволить создать «успешный» бэкап, если данные на диске уже повреждены.
* **Затрагиваемые файлы:**
  * `mobile/lib/data/vault_store.dart`
* **Шаги реализации:**
  1. В методе `backup()` перед формированием архива провести dry-run проверку целостности:
     * Для каждой книги каталога выполнить пробное чтение/проверку AEAD (`_get('objects', b.objectId)`).
  2. При обнаружении сбоя целостности сразу сообщать пользователю о повреждении конкретного объекта, не вводя в заблуждение успешным созданием битой резервной копии.

---

## Этап 2: Обновление криптографического протокола (Формат v2)

### Шаг 5. Исправление SEC-02: Cryptographic Domain Separation (Разделение доменов)
* **Цель:** криптографически разделить контексты шифрования книг и снимков каталога, исключив возможность подмены каталога пользовательским файлом.
* **Затрагиваемые файлы:**
  * `mobile/lib/data/vault_store.dart`
  * `mobile/lib/data/crypto_codec.dart`
  * Десктопное Go-ядро (`internal/vault/`)
* **Шаги реализации:**
  1. **Разделение доменов в KDF и AAD:**
     * При выводе ключа объекта передавать тип сущности в KDF-контекст:
       `codec.objectKey(master, vaultId, '$kind:$id')`
     * В AEAD в качестве ассоциированных данных (AAD) передавать не просто `$id`, а строку с префиксом типа:
       `'$kind:$id'` (например, `'snapshot:<id>'` и `'object:<id>'`).
  2. **Версионирование и миграция:**
     * Увеличить версию формата в `vault.json` (`version: 2`).
     * При открытии архива `v1` предусмотреть миграцию: перешифровать снимок каталога с новым префиксом домена и обновить версию в заголовке.
  3. **Синхронизация с десктопом:**
     * Внести аналогичные изменения в Go-пакет `internal/vault`, обновить кроссплатформенные тестовые векторы (`mobile/tool/go_vectors.go` и `mobile/test/fixtures/go-vault-v1.json` -> `v2`).

## Проверка и верификация после исправлений

После реализации каждого шага:
1. Запустить набор тестов аудита:
   ```sh
   cd mobile
   flutter test test/security_audit_test.dart
   ```
2. Перевести тестовые утверждения (assertions) из режима воспроизведения уязвимости (`REPRO`) в режим подтверждения защиты:
   * Тест `SEC-01`: проверять, что при блокировке `documents.written` равен `null`, а попытка завершить экспорт отклоняется.
   * Тест `SEC-02`: проверять, что подстановка объекта вместо снимка каталога вызывает ошибку аутентификации `LibraryFailure`.
   * Тест `SEC-03`: проверять, что вложенный FB2 либо отвергается по лимиту, либо не раздувает текст в памяти.
   * Тест `SEC-04`: проверять, что восстановление бэкапа с лишними файлами отклоняется.
   * Тест `SEC-05`: проверять, что бэкап повреждённого хранилища выбрасывает ошибку аутентификации.
3. Убедиться, что остальные тесты приложения продолжают проходить:
   ```sh
   flutter test
   ```
